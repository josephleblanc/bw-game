# Backlog

Deferred-but-wanted work, tracked so nothing rots silently. The weekly
perf-trend job renders every open item below (with its age) into the
[perf-review](docs/perf-review.md) report; anything older than two weekly
cycles without progress is flagged there for a schedule / split / close
decision.

Conventions (what `cargo xtask perf report` parses):

- one item per line under `## Open`: `- [ ]` open, `- [x]` done
- short id in bold, then the description
- `Added YYYY-MM-DD.` at the end so age is computable

Close an item by checking its box; move it to Done when archiving.

## Done

- [x] **action-states** — The walker's action layer, tier 1 of docs/animation/animation-set.md (mechanisms 1–2: additive layer + one-shot-with-recovery). `bw_core::character` grew a vertical channel — `y`/`vy` ballistics at `JUMP_V0`/`GRAVITY` (apex ≈ 0.28 m, air ≈ 0.48 s), requests honored only while grounded, the stride freezing mid-air because cycles lock to ground contact, and touchdown arming a landing absorption (root dip + knee take-up over `LAND_WIN`, dip matched to the leg shortening so feet stay planted) — plus an airborne tuck (thighs forward, knees up, feet pointed, arms spread) and a one-shot punch (`Option<f32>` phase over `PUNCH_DUR`; windup/strike/recover envelopes additive on the right arm with torso coil/lean and a left-arm guard; requests mid-action ignored; envelopes zero at both ends so the gait swing resumes bit-for-bit). `MovementInput` carries level-triggered `jump`/`punch` bits — the state machine itself guards double impulses and restarts, so held keys read as bounce and chained cycles. Eight new core tests pin ballistics, mid-air input immunity, absorption planting, tuck, one-shot semantics, strike geometry (forward reach, straight elbow), gait composition, and determinism; the steady-alloc gate now drives bounce/flurry inputs through its measured window (still 0 blocks). Viewer: Space jump, F punch (P takes over pause), an action readout, and the `--viewer-shot` smoke now captures four tagged shots — walk, mid-air (HUD reads the 0.30 m apex), strike (the punch window arcs the figure so the trailing camera sees the extended arm side-on — a strike straight down the camera axis foreshortens to nothing), run — all verified from the captures. Added 2026-09-22. Done 2026-09-23.
- [x] **mandala-stress** — The walker-gallery stress scenes: `mandala-100`/`mandala-1k`/`mandala-10k` — 100/1,000/10,000 figures on interlocking loops: every figure walks a circle of one shared radius and speed, but the centers are scattered (jittered sunflower) with alternating directions and seeded phases, so paths cross in constant near-miss traffic with no ring gaps. Zero new sim code — every figure is a `CirclePath` walker, so the measured path and its zero-steady-alloc proof carry over unchanged (verified: 0 blocks/tick at 10k, ~2.6 ms/tick p50 for 130k segments). `mandala-view` (dev-only `viewer` feature) paints it: each figure's color is frozen at spawn from a procedural painting (blue/red circles, rotated purple square, orange square, green ring on ink) sampled at its t = 0 tile — at t = 0 the crowd reads as colored tiles forming the image, the loops dissolve it, and since all loops share the period `T₀ = 2πr/s` the painting snaps back every ~9/25/71 s. Palette = exactly the painting's 6 colors (assigned by handle at spawn, never mutated), so batching is trivial at 10k.
